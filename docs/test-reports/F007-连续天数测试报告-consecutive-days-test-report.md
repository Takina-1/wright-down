### 缺陷与复测

| 缺陷编号 | 复现条件与现象 | 是否阻塞验收 | 修复版本 | 复测结果与证据 |
|---|---|---|---|---|
| D-01 | 连续天数在真机上恒为 0。根因：`computeStreak` 把带时刻的「今天」（生产环境 `DateTime.now()`）直接减一天，得到的「昨天」也带时刻，与 `dayKey` 解析出的 naive 日期（00:00）不相等，`DateTime` 相等性按 microseconds 比较，集合查找全部落空 → `current` 恒为 0；`hasEntryToday` 因走 naive 解析而未受影响，故 Oct-31 场景下显示的「1 天」实为 `current=0` 与 `hasEntryToday=true` 拼出。宿主单测全部用午夜 `today`，`subtract(Duration(days:1))` 恰好落在午夜，掩盖了该问题 | 是 | `feat/F007-consecutive-days`（本轮修复 `client/lib/src/domain/streak.dart`） | 修复方式：统一用 naive 日历日运算——入口用 `_dayOf()` 截断时刻，退日用 `_shiftDays()` 走 `DateTime` 构造器的日期溢出规则（月末/跨年/闰日），不再依赖 `Duration`。宿主侧新增 4 项带时刻的回归测试（修复前 3 项失败、修复后全过），全量 `flutter test` 由 297 增至 301 项全通过，`flutter analyze` 无问题；真机侧重建并重签名安装后复测 TC-16/TC-18/TC-20/TC-21/TC-22/TC-23，数字全部由错误的 0 变为预期值（TC-16 由 0 → 1、TC-22 由 0 → 2、TC-23 由 0 → 3） | 已修复并复测通过 |
