## 1. 用户场景与目标

写日记的动力很大一部分来自「已经连续记了几天」这种看得见的积累。当前应用回顾页顶部只有时间轴，用户打开回顾页看不到自己坚持了多久，缺少继续写下去的即时反馈。

本次要在回顾页顶部放一张「连续天数」卡片，让用户一眼看到当前连续记录了多少天，并在当天还没写时轻推一句「今天还没记」。

连续天数是**纯本地计算**：从已存条目的 `dayKey` 字段算出连续日历日的天数，不依赖网络、不新增数据字段、不引入服务器。

## 2. 范围与边界

- 本次实现：
  - `domain` 层新增纯函数连续天数计算：输入一组 `dayKey`（`YYYY-MM-DD`）与「今天」的日期，输出「截止到昨天的连续天数」与「今天是否已记」。
  - 回顾页（TimelinePage）顶部新增「连续天数」卡片：显示 emoji + 文案「连续 N 天」；当天未记时附「今天还没记，去写一条」行动按钮。
  - 空状态：无任何记录时卡片显示「开始记第一条，开启你的连续记录」。
  - 计算口径与边界（空数据、单条、跨月跨年、跨闰年、当天已记/未记、删除后减少）写进验收标准并配单元测试。

- 本次不实现：
  - 历史最长连续天数（`longest`）——本次只算「当前连续」，避免范围膨胀；算法预留扩展位但不实装。
  - 热力图、月度回顾、关键词云、AI 情绪分析（见 [产品设计](../产品设计-product-design.md) §二未做清单，属 Phase 3 后续）。

## 3. 验收标准

计数口径统一说明：**连续天数 = 从昨天往回连续有记录的天数**。今天还没写时，数字**不**包含今天；今天写了，数字才包含今天。这样午夜之后数字不会因为「今天还没写」而虚增或跳号。

| 编号 | 前置条件 | 用户操作或触发事件 | 可观察的预期结果 |
|---|---|---|---|
| AC-01 | 回顾页有若干条目 | 打开回顾页 | 顶部显示「连续天数」卡片，正文含「连续 N 天」（N 为截止昨天的连续天数） |
| AC-02 | 昨天及之前连续有记录，今天还没写 | 打开回顾页 | 卡片显示「连续 N 天」并显示「今天还没记，去写一条」行动按钮 |

## 5. 实现方案

### 5.1 页面与状态变化

回顾页（TimelinePage）顶部新增一张卡片，与时间轴并列：

```text
┌─────────────────────────────┐
│ 🔥 连续 N 天                │
│ 今天还没记，去写一条  [写一条] │  ← 今天未记时
└─────────────────────────────┘
```

- 卡片文案、emoji、空状态文案由 UI 层决定；domain 层只提供 `连续天数` 与 `今天是否已记` 两个纯数据。
- 卡片本期不响应点击（见 §2 未决定项）。

### 5.2 数据流、模型与接口

domain 层新增纯函数（零框架依赖，符合 Local-First 三条铁律）：

```dart
/// 连续天数计算结果。
///
/// 计数口径为「昨天为界」：`current` 是截止到昨天的连续天数；
/// `hasEntryToday` 表示今天是否已写。今天还没写时 `current` 不含今天，
/// 避免午夜后数字虚增或跳号。
class StreakSummary {
  const StreakSummary({required this.current, required this.hasEntryToday});

  /// 截止到昨天的连续天数。
  final int current;

  /// 今天是否已写至少一条。
  final bool hasEntryToday;
}

/// 由一组 dayKey 计算连续天数。
///
/// [dayKeys] 为本地日历日字符串（YYYY-MM-DD），内部去重排序；
/// [today] 为「今天」，默认取当前本地日期。
StreakSummary computeStreak(Iterable<String> dayKeys, {DateTime? today});
```

算法：

1. 把 `dayKey` 去重，只保留合法的 `YYYY-MM-DD`（与 F004 对 `dayKey` 的校验口径一致；非法值跳过，不让脏数据让计算崩溃）。
2. 以本地日历日为粒度，从 `today` 的**昨天**开始逐日往前找连续命中；命中天数即 `current`。
3. `hasEntryToday` 由 `today` 本身是否在 `dayKey` 集合里判定。
4. 若昨天没有任何记录，`current = 0`（即使今天写了也不从今天往回算——这是「昨天为界」的语义；今天写了的计数体现在下一次「昨天」时）。

> 口径示例（`today = 2026-10-31`）：
> - `{10-30, 10-29, 10-28}` → `current = 3`（昨天 10-30 起连续 3 天），`hasEntryToday = false`。
> - `{10-31, 10-30, 10-29}` → `current = 2`（昨天 10-30 起连续 2 天，今天 10-31 另算），`hasEntryToday = true`。卡片可显示「连续 3 天」把今天并入，或显示「连续 2 天」+已记今天——UI 取 `current + (hasEntryToday ? 1 : 0)` 展示「含今天的连续天数」，避免口径混乱。

### 5.4 离线、权限拒绝、失败与恢复

- 纯本地计算，无网络依赖，离线照常可用。
- 纯函数无 I/O，不会失败；非法 `dayKey` 跳过而非抛异常（与 F004 脏数据退回口径一致，不让回顾页崩溃）。

### 5.5 数据迁移与兼容性

- 不新增数据库字段、不升 schema、不改备份格式（`dayKey` 是 F001 已有字段）。
- 与 [产品设计](../产品设计-product-design.md) 的差异：产品设计 §5「回顾模块」把「连续天数」列为 v1 集合之一，本次落实该入口；未改变共用架构。产品设计 §11 提到「连续天数弱化」，本次仅做计数卡片，不做热力图与统计页，符合该定位。
