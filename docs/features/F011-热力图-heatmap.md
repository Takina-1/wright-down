## 1. 用户场景与目标

用户写日记一段时间后，想知道自己哪些天写得多、哪些天没写，直观看到坚持的节奏。当前回顾页只有时间轴和连续天数，缺少一个一眼能看出「哪天写了几条」的日历视图。本次做一个日历热力图：每个格子代表一天，颜色深浅表示当天写了几条日记，让用户一眼看到自己的记录密度。纯本地计算，不依赖网络、不引入服务器。

## 2. 范围与边界

- 本次实现：
  - `domain` 层新增纯函数 `buildHeatmap`：输入一组 `dayKey`（`YYYY-MM-DD`），输出最近 84 天（12 周）的网格数据（每日条数 + 强度等级 0-4）。
  - 新增统计页（`StatsPage`）：日历网格 + 热力着色（条数越多颜色越深），带星期表头与月份标签。
  - 入口：「我的」页加「📊 统计」ListTile，点进去看热力图。
  - 边界（空数据、单天多条、跨月网格、非法 dayKey、强度分级）写进验收标准并配测试。

- 本次不实现：
  - 月度情绪统计、关键词云、AI 分析（见产品设计 §二延后项）。
  - 「去年今天」回顾卡片。
  - 点击热力图格子跳详情。

- 前置依赖：F001（本地记录，dayKey 字段）。

- 未决定的问题及影响：无。

## 5. 实现方案

### 5.1 页面与状态变化

统计页（StatsPage）：顶部标题「记录热力图」，下方是 7 列日历网格（周一到周日），每格是一个日期，颜色按当天条数着色。网格上方有星期表头（一/二/三/四/五/六/日），左侧或顶部有月份标签。空状态时显示「还没有记录」。

入口：「我的」页在「导出与备份」上方加一个「📊 统计」ListTile。

### 5.2 数据流、模型与接口

domain 层新增纯函数（零框架依赖，符合 Local-First 三条铁律）：

```dart
/// 一天的热力格子。
class HeatmapCell {
  const HeatmapCell(this.dayKey, this.count, this.level);
  final String dayKey;       // YYYY-MM-DD
  final int count;           // 当天条数
  final int level;           // 0~4，条数越多越大
}

/// 由一组 dayKey 生成最近 [weeks] 周（默认 12 周 = 84 天）的热力网格。
///
/// [dayKeys] 可以是含非法值的混合集合：非法值跳过。网格从「今天往前推 weeks*7 天」
/// 的第一天开始，按周一到周日排列。强度等级按条数分档（见 [levelOf]。
List<List<HeatmapCell>> buildHeatmap(List<String> dayKeys, {int weeks = 12});
```

强度分级（`levelOf(count)`）：0 → 0；1 → 1；2~3 → 2；4~6 → 3；≥7 → 4。UI 按 level 取色。

统计页从 `repository.exportAll()` 取全部条目（含已删除），过滤 `isValidDayKey` 后调用 `buildHeatmap`。已删除条目也计入历史密度（用户想看整体节奏，删除的也算写过）。

### 5.4 离线、权限拒绝、失败与恢复

- 纯本地计算，无网络依赖，离线照常可用。
- 纯函数无 I/O，不会失败；非法 `dayKey` 跳过而非抛异常（与 F004/F009 脏数据退回口径一致，不让统计页崩溃）。

### 5.5 数据迁移与兼容性

- 不新增数据库字段、不升 schema、不改备份格式（复用 F001 已有的 `dayKey`）。
- 与 [产品设计](../产品设计-product-design.md) 的差异：产品设计 §5「回顾模块」把「热力图」列为 v1 集合之一，本次落实该入口；未改变共用架构。

  - 强度分档固定：0 条→0、1 条→1、2~3 条→2、4~6 条→3、≥7 条→4；UI 按等级取 primary 的 0.2/0.35/0.55/1.0 透明度，0 级用 surfaceContainerHighest。

  - 统计页从 `exportAll()` 取全部条目，按 `dayKey` 聚合；非法 dayKey 跳过（复用 F001 的 `isValidDayKey`）。
