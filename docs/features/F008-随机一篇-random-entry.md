## 1. 用户场景与目标

打开回顾页时，顶部除了连续天数，还想有一个「随便看看」入口：从已有日记里随机抽一篇，让用户在不知道该看什么时有个轻量的起点。纯本地计算，不依赖网络、不新增数据字段、不引入服务器。

## 2. 范围与边界

- 本次实现：
  - `domain` 层新增纯函数 `pickRandomEntry`：从一组未删除条目里随机抽一条。
  - 回顾页顶部新增「🎲随便看看」卡片：显示抽中条目的摘要与日期，点击进详情，提供「换一篇」重新抽。
  - 空状态：无记录时卡片显示引导。
  - 边界（空数据、单条、多条、固定种子可复现）写进验收标准并配测试。

- 本次不实现：
  - 历史回顾卡片（去年今天、月度回顾）——见产品设计 §二延后项。
  - 关键词云、AI 情绪分析。
  - 按标签/日期范围筛选后随机。

- 前置依赖：F001（本地记录）、F005（删除记录与回收站，提供未删除条目过滤）。

- 未决定的问题及影响：无。

## 5. 实现方案

### 5.1 页面与状态变化

回顾页（TimelinePage）顶部新增一张卡片，与连续天数卡片上下排列：

```text
┌─────────────────────────────┐
│ 🎲 随便看看                  │
│ 抽中条目摘要…                 │
│ 2026-10-28        [换一篇]   │
└─────────────────────────────┘
```

- 卡片文案、emoji 由 UI 层决定；domain 层只提供抽中的 `Entry`。
- 抽中逻辑：打开回顾页时抽一次，点「换一篇」重新抽。

### 5.2 数据流、模型与接口

domain 层新增纯函数（零框架依赖，符合 Local-First 三条铁律）：

```dart
/// 从一组未删除条目里随机抽一条。
///
/// [entries] 应为未删除条目；空集返回 null。
/// [random] 用于测试注入固定种子，生产默认取系统随机源。
Entry? pickRandomEntry(List<Entry> entries, {Random? random});
```

算法：
1. 空集返回 null。
2. 用 `Random`（默认系统源，测试可注入固定种子）取索引 `[0, entries.length)`。
3. 返回对应条目。

回顾页从 `repository.exportAll()` 取全部条目，过滤 `!isDeleted`，调用 `pickRandomEntry`。

### 5.3 受影响模块／文件

```text
client/lib/src/domain/random_entry.dart              新增：pickRandomEntry 纯函数
client/lib/src/ui/timeline_page.dart                 回顾页顶部新增随机一篇卡片
client/test/domain/random_entry_test.dart            新增：纯函数单测覆盖 AC-07
client/test/ui/timeline_page_random_test.dart         新增：组件测试覆盖 AC-01~AC-06
```

新增依赖：无。

### 5.4 离线、权限拒绝、失败与恢复

- 纯本地计算，无网络依赖，离线照常可用。
- 纯函数无 I/O，不会失败；空集返回 null 而非抛异常。

### 5.5 数据迁移与兼容性

- 不新增数据库字段、不升 schema、不改备份格式。
- 与 [产品设计](../产品设计-product-design.md) 的差异：无。产品设计 §11 把「🎲随便看看」列为回顾页顶部卡片之一，本次落实该入口。
