## 1. 目标与范围

打开应用即可写文字，停输 1 秒自动保存到本地 SQLite；可在回顾列表查看和编辑，关闭应用后仍可读取已保存内容。未注册、断网时功能可用。

本次不实现语音、图片、标签、账号、服务器、云同步、随机回顾和热力图。应用名称暂用“本地日记”，包名使用开发占位；本次不是可提审版本。

## 2. 验收标准

| 编号 | 场景 | 预期结果 |
|---|---|---|
| AC-01 | 未登录、断网输入非空正文 | 停输 1 秒触发本地保存，落库成功才显示“已保存” |
| AC-02 | 保存后关闭并重新打开数据库／应用 | 回顾列表可读取完整正文、创建时间和本地 dayKey |
| AC-03 | 同一条连续编辑、多次自动保存 | 更新原条目，不产生重复日记；慢写入不会覆盖更新的输入 |
| AC-04 | 点击“下一条”或切换回顾页 | 先完成待保存内容；保存失败留在当前编辑页，文本不清空 |
| AC-05 | 注入本地写入失败 | 显示保存失败与重试入口；重试成功后状态恢复 |
| AC-06 | 空白输入、空列表 | 不创建空白条目；空列表提供开始记录入口 |
| AC-07 | 从回顾选择已有记录并编辑 | 保留 ID 与创建时间，更新正文及修改时间 |
| AC-08 | 列表超过一页／创建时间相同 | 按创建时间与 ID 降序进行 Keyset 分页，无重复遗漏 |
| AC-09 | 系统返回或进入后台 | 尝试立即保存；应用内返回保存失败时不直接退出，可继续编辑或明确放弃 |
| AC-10 | Android 工程 | 分析、适用测试与 APK 构建通过；真机生命周期和离线行为另记实测结果 |

落库前的输入在系统强制终止、断电等情况下仍可能丢失，不承诺尚未保存内容的强杀恢复。

## 3. 方案与参考

- Flutter + Dart；Android 为当前目标；SQLite 使用 sqflite，宿主集成测试使用兼容的 FFI 工厂。
- 按 Flutter 目录约定将 `client/src` 调整为 `client/lib/src`，`client/tests` 调整为 `client/test`，保留四层职责。
- Domain：纯 Dart 的 Entry、游标与 LocalEntryRepository 接口。Data：SQLite 存取。UI：编辑状态、自动保存调度和页面。Platform 留待系统能力。
- 单次编辑会话复用同一个条目 ID。保存串行执行，状态绑定当前正文版本；错误保留文本，显式重试。
- 编辑已有条目清空正文时不覆盖为无效空记录，提示输入内容；本次不提供删除功能。
- 回顾页按月分组，每页 30 条，以 `(createdAt, id)` 作为稳定游标；保存后重新加载首屏。
- 三个导航入口为记录、回顾、我的。“我的”说明当前本地存储及卸载会删除本地数据，提供本地数据说明；无广告、统计或云 SDK。
- 保留原设计的文字页自动聚焦；“下一条”仅作为条目边界，无独立保存按钮。首版专注文字，语音入口待对应功能实现。
- Daily You 参考无需账号的体验，DiaryVault 参考自动保存行为；本次独立实现，不复制其源码。官方 SQLite 指南：https://docs.flutter.dev/cookbook/persistence/sqlite 。

## 5. 环境与限制

初始机器未发现 Flutter、Java、Android SDK 命令；SDK 和缓存优先安装在项目 `.tooling/`、`.local/`（不纳入版本控制）。初始目录不是 Git 仓库，因此在当前项目执行，不创建依赖已有提交的 worktree、不生成虚假的提交记录。

需要 Android 设备或模拟器才能完成真机级验收；未执行的场景会如实记录。正式隐私政策、主体信息、备案与签名发布仍属于后续上架准备。
